# Testability Review (round 2)

## Verdict: FAIL
Nearly every criterion now names a setup, an action, a stream and an exit code, and round 1's gaps are closed — but one criterion cannot pass on any commit, one asserts an exit code the requirement it implements says is unchanged (it isn't), and every "from the root / from inside an instance" criterion is underdetermined because an environment variable short-circuits the resolver the whole teardown half rests on.

## Untestable Criteria

1. **Platforms: "`GOOS=windows go build ./...` succeeds"**: it does not succeed on the parent commit, and nothing in this feature would make it. I ran it: exit 1, 17 compile errors, none in a package this change touches — `internal/cli/sessionattach` (`syscall.Flock`, `LOCK_EX`, `LOCK_NB`, `Stat_t`, `Kill`, `SysProcAttr.Setpgid` in `attach.go`, `detach.go`, `supervise.go`, all with no build tag) and `internal/promptcapture/terminal.go` (`SIGTSTP`, `SIGCONT`, `Getpgrp`, `unixTcgetpgrp`). There is no windows build in CI either (`.github/workflows/test.yml` has no `GOOS` step). The criterion is unsatisfiable as written. -> Narrow it to what this change adds: "`GOOS=windows go build ./internal/configdir/` succeeds" (plus `./internal/testhook/` if that lands), and keep the separate clause about the fallback file's comment.

2. **"At the same root, `niwa worktree create`, `apply <x>`, `attach <x>`, `detach <x>` and `niwa go <repo> <x>` ... each print the R10 root-level error on stderr and exit 1."**: bare `niwa worktree create` at the root exits **2** today, not 1 — `internal/cli/session_lifecycle_cmd.go:161` returns `ExitCodeError{Code: 2}` from the repo-inference failure, and that error does not come from the mapping store. So R10's rationale ("Each already exits 1 at the root today, with a misleading error read from the mapping store, so only the message changes") is wrong for `create`, and the criterion silently changes an exit code that R21 says existing invocations keep. A tester has two documented expected values and no way to choose. -> Either record `create` at the root moving 2 -> 1 as a named exception to R21, or assert each command's current code and change only the message.

3. **Every criterion anchored to a working directory** (destroy from the root, from another instance, from inside a worktree; the whole R10 root table): `resolveInstanceRoot` (`internal/cli/session.go:137`) returns `NIWA_INSTANCE_ROOT` **unvalidated, before any cwd classification**, and roughly 31 call sites across `internal/` and `test/` set it — including most existing worktree unit tests. The PRD never says whether that override bypasses the new root refusal or session resolution. That answer decides the expected result of six criteria and whether the criterion "the existing destroy unit and functional tests pass unchanged" can hold at all (a guard placed after the env check is invisible to those tests; one placed before breaks them). -> Add a clause to R3/R10 stating what `NIWA_INSTANCE_ROOT` means for session resolution and the root refusal, and one criterion asserting it.

4. **The "(pre-fix fails)" marker on the five forced concurrency criteria** (two overlapping refreshes, mapping write, mapping delete, reaper read mid-swap, root `instance.json` read): the preamble defines the marker as "must fail against the code before this change", but no seam exists on that code to force any of those interleavings. `materializeAndSwap` runs straight-line from `preserveSessionMappings` (`internal/workspace/snapshotwriter.go:464`) to `SwapSnapshotAtomic` (`:469`) with nothing between them, and `testfault.Maybe` can only *return an error* — it cannot park a goroutine, and its only swap-adjacent label (`snapshot-swap`, `internal/workspace/snapshot.go:58`) sits before the first rename. The real failing baseline is the parent commit **plus** the no-behaviour-change hook commit the design lands first. As written the marker names a commit the test cannot run against. -> Say it: "pre-fix fails" for forced criteria means failing on the commit that adds the hook points and nothing else.

5. **"With the bound set to 1 second, a command blocked for 3 seconds on the configuration directory exits non-zero within 2 seconds ..."**: two things are missing. It never says what holds the directory for those three seconds (which lock, held by whom), and "a command ... exits" reads process-level while "the bound set to 1 second in the test" is only reachable in-process — R17 says the constant is one "that tests can override" without saying how, and every comparable knob in this repo is a `const` whose only override is an environment variable (`NIWA_REAP_IDLE_GRACE`, `internal/cli/reap.go:45`; `NIWA_DESTROY_GRACE_SECONDS`). If this is a functional test against the real binary there is no override and the criterion cannot be written. -> Name the holder ("a second acquisition holds the directory's lock for 3 seconds") and say whether the override is a package variable (so this is an in-process test) or an env var (so it can be command-level). The same ambiguity applies to the fetch-held-for-3-seconds criterion above it.

## Missing Test Coverage

1. **R9's destroyed line is never pinned**: the contract is `session: destroyed <worktree-id> (<repo>) at <path>`; the line today is `session: destroyed <sessionID>` (`internal/cli/session_lifecycle_cmd.go:593`). The only criterion that touches it requires "one `session: destroyed` line" — which the current format already satisfies. Goal 2 and the cleanup-script story rest entirely on this line, since destroyed and nothing-to-destroy both exit 0. Missing AC: one criterion asserting the full line shape including the repo and the path.

2. **R10's completion and WorktreeRemove-hook rows have no criterion**: both reach the workspace through the same `resolveInstanceRoot` this change rewrites. `completeSessionIDs` (`internal/cli/completion.go:97`) is the `ValidArgsFunction` for `apply`, `destroy`, `attach` and `detach` and swallows all errors to an empty list; `runFromHookRemove` (`internal/cli/session_from_hook_cmd.go:249`) must keep returning nil (exit 0) because WorktreeRemove is non-blocking. A refusal placed in the shared resolver can turn completion into a silent break and the hook into a non-zero exit that fails Claude's worktree removal, and nothing would catch either. Missing ACs: completion at a multi-instance root returns no candidates and no error; `niwa worktree from-hook` for WorktreeRemove at the root exits 0 and emits only its existing warning.

3. **R3's "From any directory outside the workspace, the command fails as it does today"**: no criterion. Missing AC: from outside, destroy by session id and by worktree id still exit 1 with `not inside a workspace instance (no .niwa/instance.json found walking up from <cwd>)`.

4. **R2's "taken in worktree-id order"**: no criterion ever destroys two worktrees successfully — the two-worktree criteria each refuse one and destroy one, so stdout carries a single line and the ordering clause is never observed. Missing AC: a session whose instance has two clean active worktrees prints two destroyed lines in worktree-id order. (Enumeration is already deterministic — `ListSessionLifecycleStates` uses `os.ReadDir` over `^[0-9a-f]{8}\.json$` — so this is cheap to assert.)

5. **R9's "Exit 2 stays the usage-error code"**: no criterion, even though the two new codes land immediately next to it. Missing AC: destroy with no id, and with both an id and `--by-path`, each still exit 2 with their current usage lines.

6. **R15 at command level**: the forced criteria cover the reaper's read and teardown's read in isolation, and the preamble's "forced tests against that writer are the accepted proof" is scoped explicitly to R11-R13, not R15. Goal 4 and the last user story are about `niwa reap` running while dispatches provision. Missing AC, or extend the preamble sentence to R15 so the omission is deliberate rather than an oversight.

7. **R4's uppercase/short/non-hex cases are asserted only against a handle**: "The first 7 characters of a matching handle, the uppercase form of a matching handle, and a non-hex value each exit 3" does not cover the same three forms against a *handle-less* mapping's session-id prefix, which is the branch R4 restricts to "exactly 8 lowercase hex characters". Missing AC: 7 characters of, and the uppercase form of, a handle-less mapping's session-id prefix also exit 3.

## Other findings

**Exit codes 3 and 4 are not new to this command group.** `niwa worktree attach` already exits 3 ("attach lock is held", `internal/cli/sessionattach/attach.go:99`) and `niwa worktree detach` exits 3 (live holder) and 4 (killed live holder, empty message) at `detach.go:79,98`, documented in `docs/prds/PRD-niwa-session-attach.md`. The Decisions section's "Codes 3 and 4 are new; 0, 1 and 2 keep their meanings" is wrong at the group level, and the cleanup-script story reads exit codes across exactly these commands. The criteria stay testable per command; the contract needs a sentence saying 3 and 4 mean different things in `destroy` than in `attach`/`detach`.

**What checks out against the code.** `SessionMapping` already carries `handle` and the ephemeral-hook writer (`internal/cli/instance_from_hook.go:217`) sets none, so R4's prefix fallback has a real population. The `niwa list` newest-mapping-per-instance tiebreak the Terms cite is real (`internal/cli/list.go` `annotateFromSessionMappings`). The attached guard reads a PID sentinel that tests already seed with their own pid, at both unit and godog level (`iSeedLiveAttachSentinelForLastSession`, `test/functional/session_steps_test.go:706`). The reaper's backstop TTL is a `const`, but `now` is a parameter and helpers already backdate instances (`reap_backstop_test.go`, and the step "the dispatch instance is aged past the backstop TTL"), so the reaper criterion's setup is reachable. A 30-second flock timeout with a `_other.go` no-op fallback and an explanatory comment already exists (`internal/workspace/codex_trust_lock_unix.go` / `_other.go`), so R17 and R20 sit on existing precedent. `niwa worktree list` at a multi-instance root prints a header plus `(no sessions match the current filter)` and exits 0 today, so that criterion's (pre-fix fails) marker lands.

**Harness work the criteria imply and that does not exist yet** (all feasible, none a PRD defect, but they belong in the plan): no step commits inside a worktree, so the unmerged-branch criteria — two of the three teardown (pre-fix fails) markers — need a new step; the only parallel runner is pty-based, which both keeps stdin open (the four-dispatch criterion says "with stdin closed") and merges stdout into stderr, so a non-pty parallel runner is needed; no step reads `SessionMapping.Handle`; and nothing anywhere in the repo kills a niwa process mid-operation — crash shapes are modelled by editing state on disk — so the two kill criteria need the re-exec runner the design describes.

**The four-parallel-dispatch marker does land.** `test/functional/features/session-message-acceptance.feature:325` deliberately scaffolds with bare `niwa init` rather than a local config repo, with a comment saying four non-GitHub provisions "collide in the shared staging directory the snapshot writer swaps through". Recomposing that scenario on a local config repo is precisely the pre-fix failure. It remains a genuine race, though, and the PRD gives no repetition count, so a single green run proves less than the forced criteria beside it.

## Summary
A test plan is writable from these criteria for roughly nine tenths of the feature — the teardown table maps one-to-one onto R9's outcomes, the forced concurrency criteria name their hold point and their assertion, and error conditions and edge cases are covered well past the happy path (ambiguity, case sensitivity, prefix length, stale and escaping instance paths, interrupted refreshes, both guard refusals). What blocks it is narrow and mechanical: the windows build criterion can never pass on any commit, the root-level `create` criterion asserts an exit code that contradicts the requirement it implements, and the `NIWA_INSTANCE_ROOT` override leaves every cwd-anchored criterion with two defensible expected results. Fixing those three, restating what "(pre-fix fails)" means for the forced criteria, and adding the seven missing ACs — chiefly the full `session: destroyed` line shape and the completion and WorktreeRemove rows of R10 — would make this fully test-plannable.
