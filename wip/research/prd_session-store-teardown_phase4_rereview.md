# PRD Re-review

## Verdict: FAIL
The rewrite resolves nearly all first-round findings, but it adds two internal contradictions in the teardown outcome contract and leaves R23 without an acceptance criterion. Each needs a one-sentence fix, not a redesign.

## Unresolved first-round findings

1. **Other readers of a transient `.niwa` (completeness #17), ephemeral-session hook part**: R15 now protects the reaper's reads and teardown's reads, and R23 stops a failed read from turning into a write. But nothing covers the hook's decision itself. A session that starts while the root directory is being swapped reads `ephemeral_session_mode` as false and silently gets no instance. That's the same class of failure as a dropped mapping, and it happens during the parallel provisioning this PRD is about. It isn't in R15, Out of Scope or Known Limitations. `config.Discover` walking up to an enclosing workspace mid-swap isn't mentioned either. -> Add the ephemeral-session hook's read of root `instance.json` to R15, with a forced AC (a hook whose read lands mid-swap still provisions an instance). Or list it in Known Limitations with the reason.

2. **Mixed-command concurrency and reap-vs-dispatch end to end (testability missing #2, #14)**: Every concurrency AC exercises either the refresh primitive or `dispatch` alone. None runs `dispatch` alongside `apply`, `create` or the hook, and none runs `niwa reap` alongside a provisioning `dispatch` at the command level, even though Goal 4 and user story 7 describe exactly that. This is minor, because R11 is written against "any caller of the snapshot refresh", so primitive-level tests can reasonably stand in. -> Either add one command-level AC (for example, `niwa reap` reaping mapping A while `niwa dispatch` provisions B: A stays gone, B is present), or say in the AC preamble that forced primitive-level tests are the accepted proof for R11-R13.

3. **No-prompts half of R21 (testability missing #7)**: `go.mod` and the functional suite are now checked, but nothing checks "prompts (none)". This is minor. -> Add "with stdin closed" to the parallel-dispatch AC and the session-teardown ACs, or drop "prompts (none)" from R21 as unverifiable.

The other first-round findings are resolved. Worktree lifecycle records in instance directories (completeness #5) and the single-instance layout (completeness #4) are scoped out explicitly with reasons (Out of Scope and Known Limitations), and that's reasonable given that instance `.niwa` directories are never refreshed. `niwa worktree list` at the root exiting 0 with a message is stated once, in R10, R21 and the Decisions section, and they agree.

## New issues

1. **R7 vs R9 "instance directory no longer exists" row, and its AC**: R7 refuses, with exit 1, any mapping whose instance path "is not an instance of this workspace". The Terms section defines that as a directory that is one of the instances niwa enumerates. A deleted instance directory isn't enumerated, so under R7 it's refused with exit 1. But R9's table and the AC "instance ... no longer exists ... exits 0" say exit 0 with a nothing-to-destroy line. Two implementers who put the checks in different orders will ship different exit codes for the most common post-reap case. -> In R7, say that a path that no longer exists is judged lexically: if its cleaned path would sit where niwa places this workspace's instances, the result is the R9 "no longer exists" row, and otherwise R7 applies. State the check order among R6, R7 and the missing-instance case (for example, R7 first, then existence, then R6), or say which outcome wins when more than one applies.

2. **R10 `destroy <anything else>` row vs R9 no-match row**: At the root, R10 gives `destroy <anything else>` the root-level message (`niwa: error: this is the workspace root, not an instance; ...`) with exit 3. R9 gives "matches no worktree and no session" the line `niwa: error: no worktree or session matches "<value>"` with exit 3. A value at the root that matches no session falls under both rows, so the stderr wording is contradictory. The AC "a value matching no worktree and no session prints the no-match line and exits 3" names no working directory, so it doesn't settle this. -> Pick one line for the root (probably R9's no-match line, since a session id is exactly what the root accepts) and change the R10 row to reference it. Then name the directory in the no-match AC: "from the workspace root and from inside an instance".

3. **R23 has no acceptance criterion**: The only root `instance.json` AC races two `create` writes. With R22's atomic write in place, that read never fails, so R23's no-write-after-failed-read rule is never exercised. The rule's second sentence ("recorded by a later command instead") isn't tested either. -> Add an AC along these lines: with root `instance.json` made unreadable, or its read forced to fail by a test hook, a `niwa create` that would record a notice leaves the file byte-identical, and a later `niwa create` with a successful read records that notice.

4. **R6 "newest mapping recorded for its instance" is undefined**: Nothing says what orders mappings: a recorded timestamp, file mtime, or the ordering `niwa list` already uses. The R6 AC ("a newer mapping from another session") inherits the gap. -> Define it, for example "newest by the same ordering `niwa list` uses to choose among several mappings for one instance", and name the field. Say what happens on a tie.

5. **R16 AC tests only the easy kill point**: R16 says "interrupted at any point". The AC kills only between staging and swap, when the live directory is still intact. The dangerous point is between the two renames, when the live directory is absent and the snapshot sits in the previous-snapshot directory. -> Add a forced kill between moving the live directory aside and moving staging into place, and assert that the next niwa command finds a usable configuration directory (with `workspace.toml` and existing mappings) without manual cleanup.

6. **R10 `niwa go` row**: The row says exit 1, and also says "for `niwa go` this changes only the message". Those agree only if `niwa go <repo> <worktree-id>` at the root already exits 1 today. The AC `niwa go <repo> <x>` also leaves `<x>` unconstrained, and `niwa go` resolves its second argument by precedence, so some values may legitimately resolve. -> State today's exit code explicitly, or drop "only the message". Constrain the AC's `<x>` to an 8-hex value that `niwa go` can't resolve any other way at the root.

7. **R21 exemption wording**: "Apart from R9's new outcome codes and R10's root-level messages" exempts R10's messages but not R10's exit codes (exit 1 for `create`/`apply`/`attach`/`detach`, exit 3 for `destroy`). The Decisions section relies on these commands already failing at the root today, and no requirement or AC states it. -> Change the wording to "R10's root-level behavior", or add a sentence saying these commands exit non-zero at the root today.

8. **`destroy --by-path` at the root is unassigned**: R1 keeps `--by-path` unchanged, but R10's table sends "`destroy <anything else>`" at the root to an error, so whether `--by-path <instance worktree path>` from the root keeps working is left to the implementer. -> Add a row to R10 saying `--by-path` behaves as today at the root.

9. **Minor wording**: (a) R9's ambiguous row requires "the R5 guidance" even for a two-mapping R4 ambiguity, where `--by-path` makes no sense. Say the guidance applies only when a worktree id is among the matches. (b) The mid-swap write AC expects "`instance.json` from that refresh", but `instance.json` is carried-over local state, not refresh output. Say "the carried-over `instance.json`". (c) R9's partial-refusal row doesn't mention kept-branch warnings for the worktrees that were destroyed. Add "plus the kept-branch warnings" to its stderr. (d) The AC "an uppercase value" should say whose value, for example "the uppercase form of a matching handle". (e) R8's "never deletes the mapping, the instance, or the repository clones" is checked only in the nothing-to-destroy AC. Add it to the first destroy AC.

Numbering runs R1-R25 with no gaps. Every cross-reference points at the intended requirement: R9's "R6, R7" and "R4, R5", R10's "R1-R9", R11 and R19's "R17", R21's "R9"/"R10", "R22 and R23", and the Known Limitations' "R12-R16".

## Summary
The rewrite fixes nearly every first-round finding. The outcome table, the per-command root table, the 30-second test-overridable bound, forced interleavings, continue-past-refusal, the any-route ambiguity rule, and ACs for overlay, global, GitHub, macOS and `go.mod` are all in place, and the lifecycle-record and single-instance scope-outs are justified. It still fails on two new contradictions in the outcome contract (a deleted instance directory against R7, and destroy at the root with a value that matches nothing, where R9 and R10 give different messages) and on R23 having no AC. Defining "newest mapping" and settling the hook's mid-swap read are the other edits worth making before resubmitting.
