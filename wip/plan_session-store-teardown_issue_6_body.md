complexity: testable
complexity_rationale: The resolution rules, matching and outcome contract are pure functions over a mapping snapshot plus a thin command wiring, so table tests and command tests cover them without new architecture.

## Goal

Resolve `niwa worktree destroy <value>` as a session id, handle or worktree id against one locked mapping snapshot and destroy that session's active worktrees under the R9 outcome contract.

## Acceptance Criteria

- [ ] `workspace.NewestMappingPerInstance(ms []SessionMapping) map[string]SessionMapping` exists, keys by `filepath.Clean(InstancePath)`, selects the latest `Created` and, on ties, the first in session-id order; `annotateFromSessionMappings` in `internal/cli/list.go` uses it in place of its inline `newest` map and the existing `niwa list` tests pass unchanged.
- [ ] A new `internal/cli/worktree_destroy_resolve.go` provides `resolveDestroyScope`, `loadMappingsForDestroy`, `matchMappings`, `resolveDestroyTarget`, `checkSessionInstance` and `destroySessionWorktrees`; `internal/worktree` is unchanged and gains no import.
- [ ] `loadMappingsForDestroy` performs exactly one mapping-store read, through the locked `workspace.ListSessionMappings`, and keeps only entries whose session id satisfies `workspace.ValidSessionID`; a test that plants an 8-hex worktree lifecycle file beside the mappings (the single-instance layout) shows it is not treated as a mapping.
- [ ] Table test on `matchMappings` covering R4: a value matches when it equals the session id, equals the recorded handle, or is exactly 8 lowercase hex characters equal to the first 8 characters of a handle-less mapping's session id; matching is exact and case-sensitive; matches are deduplicated by session id so a Codex mapping whose handle equals its session id yields one match; a mapping that records a handle is not matched by its session-id prefix; the first 7 characters of a handle, the uppercase form of a handle, and a non-hex value each match nothing.
- [ ] Table test on `resolveDestroyTarget` (pure, taking scope, value and snapshot) covering: a worktree id of the current instance resolves to that worktree; a single mapping match resolves to that mapping; no match returns an `*sessionattach.ExitCodeError` with `Code: 3` and the line `niwa: error: no worktree or session matches "<value>"`; more than one match returns `Code: 4` naming every match; and, inside an instance, a value that is both a worktree id there and a mapping match returns `Code: 4` naming both plus the R5 guidance (pass the full session id for the session, `--by-path <worktree path>` for the worktree), while the same value at a workspace root resolves to the session.
- [ ] `resolveDestroyScope` classifies the working directory through `workspace.ClassifyCwd`, yielding an instance directory inside an instance or worktree and in a single-instance-layout root, and a workspace-root scope otherwise; a directory outside any workspace fails as it does today.
- [ ] `checkSessionInstance` applies R7's rungs in order and stops at the first that applies: the recorded path is not an instance location (lexically a direct child of the workspace root other than `.niwa`) -> refusal; nothing at the path per `Lstat` -> the exit-0 "no longer exists" outcome; the path exists but, after symlinks are resolved, is not among `workspace.EnumerateInstances(root)` -> refusal; the mapping is not `NewestMappingPerInstance`'s entry for that instance -> refusal naming the newer session (R6); otherwise it returns the enumerated instance directory, never the recorded string. Unit tests cover each rung, including a recorded path outside the workspace, one equal to the workspace root, and one that is a symlink resolving outside the workspace, all of which exit 1 and destroy nothing.
- [ ] `destroySessionWorktrees` reads the instance's lifecycle records, keeps only those not ended or abandoned, processes them in worktree-id order, re-`Lstat`s the instance directory immediately before each destroy, and calls the unchanged `worktree.DestroySession` with the enumerated instance directory; before each call it verifies the record's worktree path lies under the instance's worktree directory and that its `EffectiveBranchName()` does not start with `-`, refusing that record otherwise.
- [ ] R9 success: destroying a session whose instance holds active worktrees prints one `session: destroyed <worktree-id> (<repo>) at <path>` line per destroyed worktree on stdout, each kept branch's existing `warning: branch <name> was not deleted ...` line on stderr, and exits 0; command tests cover both the merged-branch and unmerged-branch cases.
- [ ] R9 nothing-to-destroy: an instance with no active worktree prints `session: nothing to destroy: session <session-id> has no active niwa-managed worktree in <instance>; branches outside niwa-managed worktrees were not checked` on stdout and exits 0, with no worktree directory, branch, lifecycle record or mapping created, modified or removed; a mapping whose instance directory is gone prints `session: nothing to destroy: instance <path> for session <session-id> no longer exists` and exits 0; a second teardown of a session already torn down prints the first line and exits 0.
- [ ] R9 partial refusal: an instance with two active worktrees where the first by worktree id is refused by a guard (uncommitted changes in one test, a live attach in another) and the second is clean on a merged branch destroys the second, leaves the first in place, prints one destroyed line on stdout and one `niwa: error:` line per refused worktree carrying the guard's existing message on stderr, and exits 1.
- [ ] Teardown by session never deletes the mapping, the instance directory or the instance's repository clones; every session-resolved test asserts all three are present afterwards, and mapping refusals (R6, R7) exit 1 with a `niwa: error:` line naming the session and the reason having destroyed nothing.
- [ ] Every mapping-derived value printed in an outcome, refusal or ambiguity line (session id, handle, instance path, worktree path, repo) is formatted with `%q`; a test whose mapping carries a handle containing an ANSI escape sequence asserts the output shows it quoted rather than raw.
- [ ] `runSessionDestroy` routes its positional argument through the resolver, and refuses `--force` when the value resolves to a session id or handle with an `*sessionattach.ExitCodeError{Code: 2}` usage error before anything is destroyed; `--force` with a worktree id and with `--by-path` keeps today's behavior.
- [ ] A worktree-only match takes today's `DestroySession` path unchanged: destroy by worktree id and by `--by-path` inside an instance produce the same stdout, stderr and exit code as before for the merged, unmerged, attached and uncommitted cases, and `destroy --by-path <worktree path>` from the workspace root gives the same result as before; the existing destroy unit tests pass unchanged apart from the R5 collision (exit 4) and a worktree id matching nothing (exit 3).
- [ ] Session resolution gives the same result from the workspace root, from inside another instance of the workspace, and from inside a niwa-managed worktree, for both the session id and the handle, and a value matching no worktree and no session exits 3 from the root and from inside an instance.
- [ ] Forced test using `internal/testhook`: a `niwa worktree destroy <session-id>` whose mapping read lands while the workspace-root config directory is being swapped resolves the session and destroys its worktree rather than exiting 3.
