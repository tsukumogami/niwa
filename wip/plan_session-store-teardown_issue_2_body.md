## Goal

Add `internal/configdir`, the one owner of a refreshed config directory's lock, swap layout names, snapshot-marker check, staging creation, recovery rules and the `Mutate`/`Read` entry points, on unix and with a documented non-unix no-op.

## Acceptance Criteria

- [ ] `internal/configdir` exists as `configdir.go`, `configdir_unix.go` (`//go:build unix`), `configdir_other.go` (`//go:build !unix`), `recover.go` and their tests; `go list -deps ./internal/configdir` lists only standard-library packages plus `github.com/tsukumogami/niwa/internal/testhook` (no `internal/workspace`, `internal/config`, `internal/cli`), and `go.mod` gains no module.
- [ ] Layout helpers are exported and pinned by a table test for a sample directory `/w/.niwa`: `LockPath(d) == d + ".lock"`, `PrevPath(d) == d + ".prev"`, staging directories are created as `d + ".next-<random>"`, trash as `d + ".trash-<random>"`, and the stray name as `d + ".stray-<timestamp>"`.
- [ ] `HoldsSnapshot(d)` returns true when `d` is a real directory containing the provenance marker `.niwa-snapshot.toml`, true when it has no marker but contains `workspace.toml`, and false for a directory with neither, a missing path, a regular file, and a symlink pointing at a directory that would otherwise qualify (the check is `Lstat`-based).
- [ ] On unix, `Acquire(dir, mode)` opens `LockPath(dir)` with `O_CREAT|O_RDWR|O_NOFOLLOW` at mode 0600, returns an error without taking any lock when the path is a symlink or not a regular file, never unlinks the lock file (it survives a `Mutate` and a simulated swap), and retries `syscall.Flock(..., LOCK_SH|LOCK_NB` or `LOCK_EX|LOCK_NB)` every 20 ms against a deadline derived from the package variable `Timeout` (default `DefaultTimeout` = 30s, settable from tests).
- [ ] Mode semantics are proved in one process with concurrent goroutines: two `Shared` acquisitions overlap; `Exclusive` excludes both `Shared` and `Exclusive` in either order; releasing lets the waiter through; and no code path upgrades a `Shared` hold to `Exclusive`.
- [ ] The first failed (busy) try of an acquisition calls `testhook.Hit(testhook.ConfigDirLockContended)` exactly once per acquisition, and a non-nil error from that hook is returned to the caller rather than discarded.
- [ ] A timed-out acquisition returns an error naming the directory and the lock path and saying another niwa command is using it (`timed out after <bound> waiting for another niwa command using <dir> (lock <dir>.lock)`); with `Timeout` set to 1s, an acquisition blocked behind a 3-second hold returns that error within 2 seconds (PRD: blocked command exits non-zero within 2s with the directory path and "another niwa command").
- [ ] A second acquisition of a lock path this process already holds fails immediately with `nested acquisition of <dir>.lock` — the test sets `Timeout` to 1s and asserts the call returns in well under the bound — and the process-local held-path set is cleared on release, so the same path can be acquired again afterwards; the detector grants no reentry.
- [ ] `Mutate(dir, fn)` acquires `Exclusive`, runs `Recover` before calling `fn`, releases the lock before deleting any trash paths recovery or `fn` produced, and those paths no longer exist when it returns; a test proves the deletes happen after release by having another goroutine acquire the lock while a large trash tree is still being removed. `Read(dir, fn)` acquires `Shared`, calls `fn`, releases. In both, an error from `fn` propagates and the lock is still released.
- [ ] `NewStaging(dir)`, called inside `Read`, creates `<dir>.next-<random>` at 0700 containing `snap/` at 0755 and a `lock` file created with `O_CREAT|O_EXCL` that is held `LOCK_EX` for the life of the staging; the returned `*Staging` exposes the `snap/` path and a remove, and a second `NewStaging` on the same directory produces a distinct path.
- [ ] `Recover(dir)` (caller holds the exclusive lock) is covered by a case-per-rule table test: (1) `D` missing and `D.prev` a current-user-owned real directory holding the snapshot renames `D.prev` to `D`; (2) `D` and `D.prev` both real directories with `D` holding the snapshot renames `D.prev` to a trash name returned in `trash` and does not remove it under the lock; (3) both exist and only `D.prev` holds the snapshot renames `D` to `<dir>.stray-<timestamp>`, which still exists after `Mutate` returns, and renames `D.prev` to `D`; (5) a leftover `<dir>.trash-*` from a killed deleter is folded into this run's trash list and is gone after release.
- [ ] Recovery rule 4 (staging): a `<dir>.next-*` candidate is treated as dead staging only when it is a real directory holding both `lock` and `snap/`; its `lock` is opened without `O_CREAT` and tried `LOCK_EX|LOCK_NB`, so an acquirable lock means the owner died and the directory is renamed to a trash name, a lock held by a live holder leaves it in place, and a look-alike directory with no `lock` — the overlay name-collision case, an unrelated clone that merely matches another directory's `.next-*` suffix in the shared per-user overlay directory — is left untouched with no `lock` file created inside it. The legacy fixed `<dir>.next` from older binaries is the one lockless shape that is removed.
- [ ] Planted paths are refused rather than acted on: a `D.prev` that is a symlink, a regular file, or a directory owned by another user is left in place and produces no rename and no error; every removal goes through a symlink-safe remove that unlinks a top-level symlink without following it; and `RecoverMovedAside(dir)` takes the exclusive lock itself, performs only rule 1 under the same checks, and returns nil when `D` already exists.
- [ ] `configdir_other.go` builds under `!unix`, returns a no-op release with a comment stating that no ordering is provided on that platform; `GOOS=windows go build ./...` succeeds, and `go test -race ./internal/configdir/...` passes on Linux.
- [ ] Bound-related behaviour under contention: with `Timeout` set to 1s, a dispatch-shaped sequence in one process (`Read`, `Read`, `Mutate`, `Mutate`, `Mutate`, one after another) completes without a timeout, and an exclusive waiter behind a stream of repeatedly overlapping shared holds acquires within the bound.
